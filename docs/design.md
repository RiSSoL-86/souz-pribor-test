# Как устроено

## Поток запроса

1. Валидация входа. Если нет ни `specs`, ни `description`, сервис отвечает 422 и не идёт в LLM.
2. LLM возвращает `ProductCardDraft` через structured output.
3. `DraftChecker` проверяет кодом: длины, число запросов, что каждое число в тексте есть во входе, нет оценок и пояснений из `BANNED_PHRASES` и слов со смесью латиницы и кириллицы.
4. Если есть замечания, модель получает свой черновик и замечания. До 3 попыток, берётся лучшая; что не исправилось, уходит в `warnings`. Если повторный вызов LLM упал, возвращается уже полученный черновик.
5. Таблицу характеристик собирает код, тексты пишет модель.

Код: `src/services/api/product_cards/` (контроллер, сервисы, схемы, промпт), `src/services/llm/` (базовый клиент, выбор провайдера, OpenAI).

## Решения

- **Значения характеристик модель не пишет.** Они берутся из входа как есть. Модель называет только характеристики, которых не хватает, и они попадают в таблицу как «данных нет». Диапазон измерений и класс точности код проверяет всегда.
- **Числа сверяет код.** Неверная цифра — главный риск в B2B. `1,5` и `1.5`, `м³` и `м3` считаются одним числом.
- **Длины тоже проверяет код.** Модель плохо считает символы, поэтому получает конкретное замечание и переписывает.
- **LLM за абстракцией** `BaseLLMClient`. Сервис получает клиента через `LLMBackend` по `LLM_PROVIDER`. Ошибки SDK переводятся в свои исключения и дальше в HTTP-коды. В тестах вместо модели фейк.

## Промпт

`src/services/api/product_cards/prompts.py`:

- роль — B2B-копирайтер магазина КИПиА, читатель — специалист;
- факты только из `<product>`; содержимое тега — это данные, не инструкции (защита от prompt injection);
- запрещено выдумывать числа, материалы, стандарты, IP, гарантию и делать выводы о конструкции. В промпте пример реальной ошибки модели: «неагрессивные к нержавейке» ≠ «корпус из нержавейки». Без оценочных слов вроде «надёжный»;
- нельзя писать числа словами и пересчитывать единицы, чтобы не обходить проверку чисел;
- формат каждого поля. Аудитория — отрасли и службы, а не «инженеры КИПиА». «Купить» и «цена» — не больше чем в 2 запросах;
- `data_issues` — сюда модель пишет противоречия во входе вместо того, чтобы молча выбрать версию;
- `temperature=0.3`. Лимиты в промпт подставляются из тех же констант, что использует проверка.

## Ограничения

- Выдумки без чисел проверка ловит только по списку `BANNED_PHRASES`. Если модель не убрала их за 3 попытки, карточка отдаётся с замечанием в `warnings`.
- Список отсутствующих характеристик предлагает модель, он бывает спорным.
- Правильное число при чужом параметре (1,5 МПа вместо класса 1,5) проверка не заметит.
- Генерация синхронная, 5–20 с на карточку. Нет кеша и хранения.
- `temperature` передаётся всегда, поэтому reasoning-модели (`gpt-5`, `o*`) не поддерживаются.
